# OAuth sign-in in the MCP server management UI

DEPENDS ON card 62. Lets a user connect an MCP server that requires OAuth
(Linear, Notion, Sentry, etc.) from the same add/edit form that already
handles bearer tokens, per decisions/27-oauth-for-http-mcp-servers.md.

Mirrors card 39's relationship to 37: this is the UI half sitting on top of
card 62's `src/lib/mcp/oauth.ts` and the extended `McpServerAuth`. Your
surface is `src/options/components/McpServerForm.svelte` and
`McpServerRow.svelte`; do not touch `src/lib/mcp/**`.

## What to build

- `McpServerForm.svelte`: replace the always-visible bearer-token field with
  an auth-mode choice — None / Bearer token / Sign in with OAuth — mirroring
  the transport-preference `<select>` already in this form. Bearer mode
  keeps today's field exactly as-is.

  OAuth mode shows the current state (not connected / connected, token valid
  until … / needs reconnect) and a "Sign in" button. On click: resolve host
  permission for the MCP server's URL first (existing pattern,
  McpServerForm.svelte:164-194), then call
  `oauth.discoverAuthorizationServer`, request host permission for whatever
  authorization/token/registration origin(s) discovery returns (same
  `requestHostPermission` helper, called for each new origin found — all
  still inside this one click handler), then call
  `oauth.runAuthorizationFlow`. Hold the resulting oauth `McpServerAuth`
  object in local component `$state`, exactly the way `authToken` is held
  today — nothing persists until the form's Add/Save submits `buildData()`.
  A "Disconnect" action just clears that local state (and, for an existing
  saved server, persists as a cleared `auth` on the next save, the same way
  clearing the bearer token field does today).

  "Test connection" needs no changes — it already sends whatever `auth` is
  in the draft through `testMcpServerConnection`, and card 62 makes
  `client.ts` resolve an oauth token transparently.

- `McpServerRow.svelte`: add a "Reconnect needed" badge, alongside the
  existing permission badge, for a saved server whose `auth.type ===
  "oauth"` and whose token is expired with no `refreshToken` to fall back
  on. This is a best-known-state indicator (checked against the stored
  `expiresAt`), not a live probe on every render.
