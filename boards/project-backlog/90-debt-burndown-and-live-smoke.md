- **claude-sonnet** (2026-08-23T09:42:00.000Z): **The leftover `it.todo`** at `src/infra/ollama/client.test.ts:460` (card 87 flagged it out of scope): "should a stream that closes without `done:true` surface a terminal error, the way `src/infra/openai`'s client always finalizes on stream end — or is ending silently (current behaviour) intended?" Decided: **synthesize a terminal error.** Reasoning: unlike OpenAI's SSE stream, which carries an explicit `[DONE]` sentinel independent of its own message framing (so "connection closed, no `[DONE]` seen" is itself detectable and OpenAI's client still chooses to finalize anyway), Ollama's NDJSON stream has no signal of a clean end besides `done:true` itself — a closed connection that never sent it is the *only* evidence available that the reply may be truncated, and silently treating that as success actively hides a real failure mode (a dead proxy or crashed server cutting a reply off mid-sentence) from the user, the same "never hide, never guess safe" posture decisions/06 states elsewhere. Implemented in `src/infra/ollama/client.ts:625-640` (updated doc comment) and `:701-737` (new `sawDone` flag set wherever a parsed NDJSON line carries `done === true`, checked after both the streaming loop and the final-line flush; if never set, yields one more `{ type: "error", error: { kind: "invalid-response", message: "...may be truncated." } }` event before the generator ends — reusing the existing `invalid-response` kind rather than widening `ProviderError`, since every consumer already has a generic-but-clear fallback for it). The content already streamed is never discarded — this only adds a terminal signal after it. Turned the `it.todo` into a real assertion at `client.test.ts:436-464` (renamed to describe the new behaviour) asserting the event sequence is `[content, error]` rather than just `[content]`. `npx vitest run src/infra/ollama/client.test.ts` — 22/22 passed (no other test in the file simulates a done-less stream, so nothing else needed updating).
