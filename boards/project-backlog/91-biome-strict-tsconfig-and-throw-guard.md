- **claude-opus** (2026-08-23T15:05:00.000Z): **Biome's real Svelte support, probed not assumed.** biomejs.dev/internals/language-support grades Svelte ⌛️/🟡/🟡/🚫 — parsing in progress, formatting and linting experimental, no plugins — and says out-of-the-box Vue/Svelte/Astro support arrived in 2.3.0 covering "the HTML, CSS and JavaScript parts". Probing 2.5.10 directly against a deliberately mangled component showed the docs are generous: Biome formats and lints the `<script>` block ONLY. Template markup (`<div    class="a"     id="b"` split over three lines) and `<style>` (`.a{color:red}`) came back byte for byte. `html.formatter.experimentalFullSupportEnabled: true`, the flag that is meant to extend it into the markup, makes 2.5.10 skip .svelte files altogether ("No files were processed in the specified paths") — so it stays off. Two knobs were needed to make what DOES work usable: `html.formatter.indentScriptAndStyle: true` (Biome's default flattens every script block to column 0 — a whole-tree no-value diff), and a `.svelte` override turning off `noUnusedVariables`/`noUnusedImports`/`noUnusedFunctionParameters`, because Biome resolves identifiers against the script block alone and never reads the template, so anything used only from markup reads as unused (verified with a two-line counter component). All of it is written up in biome.jsonc:1-44 so the next reader does not have to re-derive it. One trap worth recording: comments in `biome.json` are silently IGNORED — Biome falls back to defaults and quietly lints node_modules and `.chrome-profile` (901 files, 11k errors). The file has to be `biome.jsonc`.
